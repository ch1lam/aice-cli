# AICE 通用 MCP 与 CUA 接入设计

状态：D1–D7 已实现，P0–P4 的实现与清理已交付；本地回归通过，外部服务及原生平台验证范围见 [验收核对](AICE_MCP_Acceptance.md)。设计日期：2026-09-27。起始代码基线：`225080b`。

本文是已批准的实施方案，不覆盖尚未变更的运行契约。按阶段实现，并把实际行为写入对应的维护文档；确定性测试、真实服务互通和原生平台证据分别记录。

当前交付、验证范围与已知限制见 [验收核对](AICE_MCP_Acceptance.md)。本文保留批准的范围与设计理由，不维护实施流水账。

## 1. 目标与审查结论

AICE 保持一个 Go binary、一个显式 Agent Loop、一套 Guard、一份追加式 Session 历史。
新增通用 MCP 接入能力；CUA 在这套能力之上接入。设计先由普通 MCP 服务的需求成立，
再迁移 CUA，不能以“从 CUA 抽出公共代码”作为通用设计的出发点。

“更好的 MCP harness”在本方案中有五个可验证的含义：

1. 模型能找到正确工具，不必预先读入全部工具 Schema。
2. 工具、服务说明和 Skill 各有明确用途，不会因接入方式改变权限。
3. 用户一次授权可以在明确范围内复用，身份变化不会沿用错误授权。
4. 超时、取消、断线不会暗中重放可能已经生效的动作。
5. 结果可理解、可追溯；裁剪给模型的上下文不破坏原始 Session 记录。

以下 D1–D7 均已获用户批准。

| 编号 | 建议决定 | 代价与边界 |
| --- | --- | --- |
| D1 | 先定义并验证通用 MCP，再让 CUA 接入 | CUA 的版本、工具清单、超时不能变成通用约束 |
| D2 | AICE 保留 Skill + CLI；受管 CUA 的动作只走 MCP | CUA 的安装、检查、系统授权仍可调用管理 CLI；不做动作 CLI 自动回退 |
| D3 | 按需发现是首个完整版本的核心能力 | 需要审查 Loop 的运行内工具选择契约，不能只加一个客户端 |
| D4 | 授权绑定服务身份与工具；复用现有 Guard | 连接授权与工具执行授权分开；既有 `--yolo` 语义保持 |
| D5 | 有序结果、结构化数据、执行状态进入可恢复历史 | 需要扩展消息/Session 值类型并验证旧历史兼容性 |
| D6 | CUA 目标为通用工具映射 + Skill；必要约束留在薄适配中 | `desktop_*` 可用于过渡，但不是永久默认；删除前必须通过行为验收 |
| D7 | 支持 stdio、Streamable HTTP、明确范围的远程认证与管理 | 不以实现所有 MCP 扩展为完成标准，不引入额外 AICE 服务或运行时 |

## 2. 为什么引入 MCP，哪些能力不应混淆

Skill 提供任务方法、工具用法和参考资源；CLI 与 MCP 提供可执行入口。
Skill 可以指导 CLI，也可以指导 MCP。添加 MCP 不要求重写已有 Bash、文件工具或浏览器 CLI。

方案批准前，CUA 已经通过专用 MCP 客户端执行，模型看到的是
`desktop_apps`、`desktop_observe`、`desktop_act`，而非 Skill + Bash 动作路线。
这是一项已有集成选择，并不证明 CUA 必须使用 MCP。当前已迁移为通用受管入口，旧包装已删除。

Cua 官方提供 MCP 和 Skill + CLI 两条入口；其运行说明明确允许在有 shell 时使用 CLI，
或使用调用方提供的现有 MCP 连接。MCP 适合 AICE 接下来要建设的统一连接、工具发现和图片结果路径，
因此本方案选择它作为受管 CUA 的动作入口。这个选择来自 AICE 的目标，不能表述成“官方只推荐 MCP”。
来源：[连接指南](https://cua.ai/docs/how-to-guides/driver/connect-your-agent)、
[运行说明](https://github.com/trycua/cua/blob/main/libs/cua-driver/rust/Skills/cua-driver/RUNTIME.md)。

两种入口可以使用相同的底层能力，但会话寿命、图片交付、调用开销和生命周期不保证等价。
同时暴露两条动作路线也没有现成证据能提高任务成功率。统一入口能减少重复工具和会话混用；
效果仍需用实际任务衡量。来源：[CLI 参考](https://cua.ai/docs/reference/cua-driver/cli-reference)、
[SDK、MCP 与托管关系](https://cua.ai/docs/concepts/sdk-mcp-and-hosting)。

## 3. 借鉴其他 harness，但由 AICE 自己制定规则

| 官方资料中的做法 | AICE 的选择 |
| --- | --- |
| Claude Code 提供延迟工具加载、Tool Search 与常驻工具设置 | 默认按需加载；提供固定入口和显式常驻选项，不能把搜索能力绑定到一个模型供应商 |
| Codex 提供本地/远程配置、认证、工具过滤、超时与审批设置 | 将配置、认证、状态、权限放进既有 app/Guard/Settings 边界 |
| OpenCode 可自动加入 MCP 工具，同时提醒工具增加上下文开销 | 自动建立目录，不等于自动把全部 Schema 放进每次模型请求 |
| Gemini CLI 提供工具/服务范围授权，并支持排除规则 | 拒绝优先，授权可复用；服务信任不等于跳过 AICE Guard |

来源：[Claude Code](https://code.claude.com/docs/en/mcp)、
[Codex](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)、
[OpenCode](https://opencode.ai/docs/mcp-servers/)、
[Gemini CLI](https://geminicli.com/docs/tools/mcp-server/)。这些是外部产品的当前参考，不是 AICE 已实现的能力。

AICE 的区别应体现在规则一致、状态清楚、失败可解释，以及有任务评测支撑；
不能仅凭功能清单宣称“最好”。

## 4. 结构和状态所有权

```text
用户配置 / 受管 CUA 配置         Skill：按需提供使用指导
            │                              │
       internal/app ──────────────── 提示组装
       配置、认证、连接生命周期、run 绑定
            │
       通用 MCP 目录与工具适配 ──────── Agent Loop
            │                         搜索后选择下一轮工具
            │                         每次执行经过 Guard
       internal/mcpclient             记录完整工具调用/结果对
       每个服务的连接、发现、调用、关闭
            │
       stdio / Streamable HTTP
            │
       普通 MCP Server / CUA Server
```

| 所有者 | 负责 | 不负责 |
| --- | --- | --- |
| `internal/app` | 配置解析、连接实例、认证协调、生命周期、run 绑定和前端命令 | 决定下一步工具动作或重试 Agent 任务 |
| `internal/mcpclient`（新增） | 单连接协议、能力协商、分页发现、通知、调用、关闭；SDK 类型止于此 | Skill 优先级、桌面状态、模型工具选择、用户权限 |
| `internal/tool` | MCP 到既有 Tool 的适配；工具搜索、资源读取、历史结果读取入口 | 全局可变工具注册中心 |
| `internal/agent` | 本次运行的可用目录视图、每轮工具选择、Guard、配对记录、停止和重试决策 | MCP SDK、进程启动、认证 UI |
| `internal/guard` | 按已绑定身份和参数判定 allow/ask/deny，复用授权 | 根据名称前缀或服务自述判断可信 |
| `internal/llm`、`internal/session` | 中立结果值类型、追加式记录与兼容回放 | 第二份 transcript 或远程服务状态恢复 |
| `internal/desktop` | 安装/系统权限、CUA 启动配置、必要桌面约束与会话清理 | 独立 MCP 协议实现 |

接口由实际消费者定义，通过构造函数在 app 装配。先采用既有官方 Go SDK；
不为本方案预建通用插件框架、事件总线、依赖注入框架或第二个 runtime。
当前依赖为 `go-sdk v1.6.1`；版本升级单独评估和回归，不与搬迁代码混为一项变更。

## 5. 通用 MCP 的行为规则

### 5.1 配置、身份与连接

在现有配置中新增 `mcp.servers` 集合。每个条目包括稳定 ID、显示名称、启用状态、
transport、连接参数、认证引用、工具 include/exclude、超时、必要性和常驻工具设置。
最终字段名在实现时与既有 Settings schema 对齐，本提案不另建配置文件体系。

- stdio 使用 executable + argv，不经 shell 拼接；工作目录明确，环境使用基础白名单与显式引用。
  不默认把 AICE 的全部供应商凭证传给子进程。动态安装命令是用户配置的执行行为，不能藏在连接逻辑中。
- HTTP 使用 MCP endpoint，支持显式凭证引用；凭证按服务/来源隔离，不因同名服务而共享。
  跨来源重定向不得携带认证头；日志、工具结果和 Session 不写 secret。
- 配置来源是身份的一部分。用户与项目的同名服务不得静默合并连接字段或借用彼此凭证。
  展示名冲突可用来源区分；模型工具名由稳定绑定生成，处理长度限制与碰撞。
- 项目配置经过现有 Project Trust。启动项目定义的命令或连接新端点还需要明确的连接授权；
  用户通过添加/启用流程确认完整连接信息可一次完成，不重复问同一问题。
- 用户级 deny 是上限，项目设置只能收紧。禁用、删除和身份变更不能被下层配置重新打开。
- 保存配置本身不启动任意子进程；“连接/测试”是明确操作。禁用服务不连接。
  默认服务可延迟连接；搜索或显式测试触发发现。必需服务可在运行准备阶段限时连接，失败则清楚报错。
- 未连接服务的名称、配置摘要和状态可被搜索；不能把“尚未获取目录”报告成“没有这个工具”。
  一个慢服务不得串行阻塞全部服务，也不能拖住普通对话。

app 拥有服务实例，客户端拥有自己创建的连接与子进程。可复用传输连接，但 run 绑定不共享可变工具选择。
关闭只处理自己拥有的资源；退出 AICE 不等于停止外部共享服务。连接数、分页数、目录大小和字节数均有边界，
到达限制返回不完整标记与下一步，而不是无限发现。

### 5.2 工具发现与上下文

模型初始获得内置工具、`tool_search`，以及受预算限制的服务摘要。
MCP 工具默认进入可搜索目录；完整 Schema 仅在选中后加入下一轮模型请求。

`tool_search` 支持自然语言搜索、按服务浏览和按完整 ID 精确选择；返回工具名称、用途、
服务身份、可用状态及权限提示。首版使用可解释的关键词匹配与排序，不引入 embedding 服务。
中文查询、英文工具名、同名工具与描述噪声都进入评测；搜索失败时必须能浏览和精确选择。

搜索同时产生一个可信的、类型化的工具选择提议。Loop 在搜索结果成功记录、工具对完整后应用它，
而不是从服务返回的文本中解析“请授予这些工具”。下一轮才给模型发送新工具的完整 Schema。
不增加任意名称都可调用的 `mcp_call` 入口来绕过定义选择。

运行规则：

1. app 冻结本次运行的配置与服务绑定；目录采用不可变修订版本。
2. `runExecution` 拥有当前选择的子集，不能修改共享的 `Loop.tools`。
3. 每次模型请求持有完整工具快照；只接受该请求中提供的工具及其 Schema 版本。
4. `list_changed` 等通知只提交失效/更新信息；在完整工具对边界刷新目录。
   已失效工具不得继续派发；定义改变后先让模型看到新定义，再产生新调用。
5. 禁用与权限撤回在派发前重新检查；运行快照不能成为继续执行的理由。
6. 恢复 Session 不恢复旧的远程 handle 或可调用集合；重新绑定后发现工具。

建议初始调优值：每次搜索最多自动选入 5 个候选；MCP Schema 预算取上下文窗口的 5%，
上限 8k token，未知窗口先用 4k。数值为待评测默认值，不是协议要求。
只淘汰完整工具定义，不截断 JSON Schema；轮次边界可淘汰不再使用的工具并明确告知模型。
单工具过大或常驻工具超预算时给出可解释错误，不发送残缺 Schema。
服务摘要同样需要总预算，不能在大量服务下绕过上下文控制。

首版不依赖供应商原生 Tool Search。未来的原生优化仍须保持相同身份、Guard 和 Session 语义。

### 5.3 服务说明、Skill、Resources 与 Prompts

服务说明作为有来源标记、受预算限制的使用资料；不提升到系统权限，也不覆盖用户指令。
保留完整文本的按需读取方式。工具描述、资源、网页或工具结果里的“免审批”都不能修改 Guard。

Skill 继续使用现有目录、信任和按需加载规则。它可以引用稳定的服务/工具 ID，
指导模型先发现再调用，但不会因为来自 MCP 就自动安装或激活。

首版提供 resources 列表与显式读取，优先支持文本、图片和资源链接。
读取动作本身经过服务范围授权；不自动抓取任意返回链接，也不自动展开大资源。
MCP Prompts、远程 Skill 自动安装/激活不在首版范围。发现到不支持的能力时明确显示支持状态。

### 5.4 权限：一次明确授权，在正确范围内复用

每次 MCP 调用仍经过注入的 Guard；身份来自 app 绑定，不能信任模型参数或工具名伪造的来源。
判定键至少包含配置来源、服务 ID、连接身份、原始工具名与有效权限范围。
远程端点/账号、stdio executable/argv 等改变时重新判断；工具 Schema 改变时使对应工具授权失效。
这些指纹用于防止误复用，不声称能证明服务行为没有改变。

| 场景 | 默认规则 |
| --- | --- |
| 新普通 MCP 工具，无已有规则 | ask；提供本次、当前 Session 的工具范围或服务范围授权 |
| 有效范围内的后续调用 | 复用授权，仍检查 deny 与当前绑定 |
| 用户级 deny、禁用或撤销 | deny；`--yolo` 不覆盖 |
| 非交互运行需要 ask | 沿用现有非交互与 `--yolo` 契约；没有有效放行则失败关闭 |
| 工具声称 `readOnlyHint` 等 annotation | 仅作提示，不据此自动放行 |
| 用户希望跨 Session 永久允许 | 显式保存用户规则；普通 Session 授权不落成永久配置 |

连接授权允许启动进程/建立连接，不自动允许该服务全部工具。
资源读取也不是天然无副作用；其授权范围必须明确。
现有 `--yolo` 仍可提升 ask，不改变 deny；本方案不暗中改变其产品含义。
协议依据：[MCP Tools 与 annotations](https://modelcontextprotocol.io/specification/2026-07-28/server/tools)。

### 5.5 结果、超时与恢复

通用结果保留有序内容块，不能把文本和图片分组后重新排列。
结构化 JSON、`isError`、服务/工具绑定和执行状态通过中立值类型记录；SDK 类型不进入 Session。
文本、图片沿用现有消息与 media 通道，结构化结果单独保留，不能塞进 Web 专用 evidence 字段。
资源链接保留来源；音频、二进制等尚不支持的模型输入明确标记，不谎报完整支持。

| 执行状态 | 含义 | 后续行为 |
| --- | --- | --- |
| 未派发 | Guard 拒绝、参数无效、发送前连接失败等 | 修复条件后可由 Loop 决定再次调用 |
| 已取得结果 | 包括 `isError`、部分结果和工具自己报告的失败 | 保留所有已收到内容，由模型/Loop判断下一步 |
| 结果未知 | 发送后超时、断线或取消，无法确认动作是否发生 | 明确提示未知，不自动重放；必要时先观察外部状态 |

客户端可重建连接；不能因重连、HTTP 重试、取消或 `isError` 自动再次执行工具。
协议级恢复若受支持，也必须证明不会二次派发，否则返回未知。
`idempotentHint` 不能单独成为自动重放的依据。调用超时可配置，CUA 保留自己的已验证超时配置。
取消请求不意味着外部动作已撤销。

区分传输/存储硬上限与模型上下文裁剪。硬上限防止无限结果进入内存/历史；
超出时记录明确的丢失标记，不承诺可找回未保存的数据。
在硬上限内，先持久化完整结果，再生成受预算限制的模型视图。
建议 `tool_result_read` 从 Session 按调用 ID 和区段读回已保存内容，不再次请求远程工具。
不创建旁路数据库或另一份 transcript。

这是显式的消息/Session 契约扩展：优先采用兼容的新增字段，验证序列化、克隆、分支、
压缩和旧记录回放。若当前版本不能无损容纳，单独评审版本迁移；不靠忽略未知字段宣称兼容。
不新增消息 Role。

### 5.6 认证与用户管理

支持 stdio 环境/凭证引用、HTTP Bearer/头部凭证引用。
远程 OAuth 首版限定为可验证的授权码 + PKCE 流程，支持预配置客户端以及标准发现下的受支持注册方式；
不承诺任意企业 SSO、设备码或私有认证协议。OAuth 的完整范围需在实现前用具体远程服务确认。
凭证持久化复用既有配置/锁边界，但按 MCP 服务隔离，不能借用模型供应商的 token。

CLI、`/mcp` 与 Settings 操作同一个 app 能力，提供添加、状态、启用/禁用、认证、重连、删除与诊断。
显示配置来源、有效工具数、已加载工具数和失败原因；区分未连接、连接中、可用、需认证、失败、禁用。
不把目录为空、权限拒绝、认证失效统称为“工具不可用”。

配置提交沿用现有空闲边界和原子写入；运行中撤销先阻止新派发，必要时通过既有停止流程取消运行。
连接测试与配置保存分开报告，外部测试失败不能被伪装成配置未保存。
不加后台文件 watcher。`/btw` 保持无工具。

## 6. CUA 如何迁移

### 最终形态

CUA 是 app 生成配置的受管 MCP 服务，使用同一个客户端、目录、结果和授权路径。
`desktop_enabled` 是受管 CUA 的唯一启用来源；MCP 页面展示该状态并跳转到同一设置。
受管 ID 保留，用户配置不能覆盖它，也不能同时注册一份相同受管连接来绕过其约束。
独立用户配置的 CUA 服务按普通服务另行授权；不能声称关闭受管开关就封禁了 Bash 或所有外部 CUA。

用户开启受管 CUA 对应现有明确的 Computer Use 授权；app 仅为审核过的工具集合和控制模式生成权限，
不因为服务名是 CUA 就允许未来新增工具。系统权限继续由 OS 管理，不新增逐应用审批。

保留以下场景责任：安装和签名身份、原生服务检查、已验证版本、启动参数与环境、
桌面会话所有权、单控制者串行执行、当前观察与目标有效性、截图坐标映射、必要清理。
其中哪些由 driver 已保证，哪些必须由 AICE 保证，要在迁移时逐项建立证据，避免重复实现。

目标模型入口是通用映射的 CUA 工具，加与 driver 版本匹配的 Skill 使用指导。
如果某项正确性约束不能由 driver 与通用边界保证，就保留最小桌面适配/执行校验；
Skill 不能代替必须强制执行的约束，也不能为追求“零特化”删除它。

### `desktop_*` 的处理规则

1. 过渡阶段可让现有工具调用通用客户端，用于保住已验证行为。
2. 同一个受管实例，一次只暴露一套动作入口。不能同时给出 `desktop_*` 和全部原始工具。
3. 对通用映射 + Skill 与现有入口进行相同任务的对比，确认会话、目标、图片、取消和动作后验证。
4. 达到验收后移除重复包装；保留的每项适配必须写明无法由下层保证的约束或评测证据。
5. 最终删除 desktop 中的私有协议连接实现。旧 Session 仍能阅读，但旧窗口引用/会话句柄不得复活。

不增加 CUA 动作 CLI 回退；失败后自动换入口会丢失会话关系，也可能重复已经发生的动作。
安装、版本、系统授权和诊断用 CLI 不构成第二条模型动作路线。

当前 CUA 固定 driver `0.29.1`；上游文档主分支可能不同。
上游 MCP 内嵌 Skill 资源可作为资料来源，但“能读取资源”不等于 AICE 已实现 Skill 自动激活。
保持现有 Skill 目录和版本匹配规则。来源：[Skill 安装指南](https://cua.ai/docs/how-to-guides/driver/install-agent-skill)。

现有平台差异必须继续记录在 [Computer Use](../desktop.md)：已有 macOS/Linux 动作问题、
Windows 原生动作验证不足，都不会因换成通用 MCP 而自动消失。迁移结论必须注明实际验证的平台和版本。

## 7. 范围与实施顺序

### 分批提交与依赖（持续目标的补充验收条件）

用户要求按行为边界合理分批 Git commit，已授权本任务的本地提交；未授权推送或创建 PR。
仅提交本任务改动，其他已有计划文件保持原状。每批记录 commit、验证结果和限制。
每单元须可构建并通过适用测试；实际边界随实现调整，不机械对应 P0–P4。

| 单元 | 问题与交付 | 依赖 | 验证与限制 |
| --- | --- | --- | --- |
| A：结果与历史 | 中立结构化结果、执行状态、绑定、克隆与兼容回放 | 无 | 结果验证、旧/新 Session、分支与压缩、三个协议投影；不宣称 MCP 已接通 |
| B：运行内工具选择 | 完整工具对之后应用可信选择，冻结请求工具集与预算 | A | 同批次越权、记录失败、失效与并发 Run；不改共享 Loop 工具表 |
| C：通用连接 | 独立 stdio/HTTP 客户端、有限发现、有序内容、无动作重放 | A | 非 CUA 本地协议 fixtures、失败/取消/上限；真实互通单列 |
| D：配置与权限 | 来源隔离、绑定身份、Guard、撤销、应用装配与搜索 | B、C | 配置优先级、授权范围、Schema 变化、非交互/yolo、端到端发现 |
| E：管理与完整体验 | CLI、/mcp、Settings、认证、resources、持久结果回读 | D | 实际 CLI/TUI、本地认证 fixtures；外部 OAuth 和搜索评测单列 |
| F：CUA 迁移 | 受管消费者、版本 Skill、必要桌面校验与移除私有协议 | D、E | 单入口、同任务行为比较、原生平台证据；删除旧入口须先满足验收 |
| G：交付收尾 | 正式指南、评测与剩余验证说明 | A–F | 全量检查、链接和旧历史；不以模拟测试代替外部/原生验收 |

SDK 保持 v1.6.1；如确需升级，另设独立审查单元和回归，不混入 CUA 搬迁。

首个完整版本包含：通用连接与用户配置、按需发现、身份授权、有序结果与历史读取、基础 resources、
上述认证与管理范围，以及完成 CUA 迁移。下面是可分别审查的小阶段，不把 P1 单独称为完整交付。

| 阶段 | 交付 | 退出条件 |
| --- | --- | --- |
| P0：合同与基线 | 明确 Loop 选择、结果字段、身份/权限规则；保存现有 CUA 行为测试与已知限制 | D1–D7 审查完成；没有把已有偏差写成新契约 |
| P1：独立通用能力 | stdio/HTTP 客户端、配置绑定、目录、基础调用与 Guard | 至少一个非 CUA 本地服务和一个非 CUA 远程服务，仅靠配置可调用；模拟服务验证失败路径 |
| P2：模型使用体验 | 发现/选择、结果裁剪与回读、resources、认证、CLI/Settings 状态 | 不依赖 CUA 的端到端任务通过；全部权限与 Session 验收通过 |
| P3：CUA 消费通用能力 | 受管配置、版本对应指导、行为比较、必要薄适配 | CUA 不持有第二套协议实现；同实例单入口；平台证据满足已声明范围 |
| P4：收尾 | 删除过渡代码、同步正式文档、记录评测 | 没有自动双路线回退，没有过时设计声明，旧 Session 可回放 |

阶段间允许内部短期兼容接线，不发布永久双客户端架构。
不在首版加入：MCP Apps、Tasks、sampling、远程代码运行环境、插件市场、任意 REST 到 MCP 转换、
远程 Skill 自动安装。未支持能力不在协议协商中虚报支持；其他反向请求返回明确不支持，不挂起等待。

SDK 升级独立提交并回归。官方 `v1.7.0` 的新默认协议路径需要验证旧协议互通，
CUA 固定要求只作用于 CUA 连接，不能锁死全局。
来源：[Go SDK v1.7.0](https://github.com/modelcontextprotocol/go-sdk/releases/tag/v1.7.0)。
新直接依赖仍遵守仓库要求，说明理由、维护和许可证后取得明确批准。

## 8. 验收与评测

### 必须通过的行为验收

- 非 CUA 的 stdio/HTTP 服务无需新增 Go adapter 即可发现和执行；分页、目录变化、同名工具、Schema 错误有覆盖。
- 多轮发现只在安全边界改变工具集合；未向模型提供的工具、旧 Schema 调用不能执行。
- 普通工具、MCP 工具与资源操作均走 Guard；同名覆盖、来源变化、端点/账号变化、撤权不能借用旧授权。
- `--yolo` 不越过 deny；非交互未放行的 ask 无外部执行；授权不会因保存 Session 变成永久配置。
- 发送后断线、取消和超时不二次派发；`isError` 中的部分图片/文本仍保留；未知结果可辨认。
- 有序文本/图片、结构化 JSON、裁剪标记在三个现有 API adapter 与 Session 回放中保持预期含义。
- 超大响应、目录上限、恶意描述、凭证日志泄漏、跨来源认证转发、挂起子进程有针对性覆盖。
- 可选慢服务不阻塞普通对话；退出只清理所属子进程；资源读取与历史回读不隐式执行动作。
- CUA 保持单控制者、有效目标、坐标与控制模式约束；取消后不盲目重放；关闭不停止外部共享 daemon。

模拟 stdio/HTTP 服务用于确定性回归，真实服务用于验证互通；不能以模拟通过替代平台原生验收。
实现检查遵循 [Collaboration](../collaboration.md)，原生/付费/外部动作验收按其现有授权要求执行。

### 判断“使用效果更好”的评测

固定模型、服务版本与任务集，对照“全量 Schema”与“按需发现”；CUA 再对照现有 `desktop_*`。
记录任务完成率、错误工具率、工具发现命中率、输入 token、首个有效动作延迟、总调用次数、
重复审批数、取消后重复动作数和结果恢复完整性。

建议先建立 50 个通用任务，目录噪声分别扩到 50/500/2000 个工具；CUA 选 20 个代表任务重复执行。
这些是评测规模建议，不是当前已有成绩。精确 ID 选择应全部正确，未知结果导致的自动重复动作必须为零。
自然语言搜索 top-5 命中率先以 95% 为调优目标；未达到时改善发现规则，不能把精确查找兜底计成命中。
任务完成率不能明显劣于基线；小样本波动需要查看逐例结果，不能用少量成功案例宣布统计优势。
延迟报告 p50/p95，并区分冷连接和热连接。
