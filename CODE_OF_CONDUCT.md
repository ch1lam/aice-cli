# Code of Conduct

AICE welcomes people of all backgrounds and experience levels. This code applies
to project issues, pull requests, reviews and other project spaces, including
maintainers and contributors.

## Expectations

- Discuss ideas and code respectfully. Give specific, constructive feedback.
- Allow questions, different experience levels and good-faith disagreement.
- Respect privacy and consent. Do not publish another person's private information.
- Avoid harassment, discrimination, threats, sexual harassment, personal attacks
  and repeated disruption. Do not retaliate against someone who reports a concern.

## Reporting

For abusive content on GitHub, use **Report content** on the relevant issue,
pull request or comment, or follow [GitHub's reporting instructions](https://docs.github.com/en/communities/maintaining-your-safety-on-github/reporting-abuse-or-spam).
These reports may go to GitHub Support; they are not necessarily delivered to
AICE's maintainer.

To request a private conversation with the project maintainer
[@ch1lam](https://github.com/ch1lam), you may open an issue asking for a private
contact channel. Include no incident details, personal information or names of
involved people in that public request. If a public request would be unsafe,
use GitHub's reporting channel instead. Security vulnerabilities have a separate
[private reporting process](SECURITY.md).

## Enforcement

Maintainers may ask participants to change their behavior, remove disruptive
content, restrict participation or block an account, depending on severity
and repetition. Apply these rules consistently, including to maintainers.
Share report details only as needed to investigate and respond.

A participant may request reconsideration with relevant context through the
same private contact channel. Concerns involving the maintainer can be reported
to GitHub when they violate GitHub's community rules.
